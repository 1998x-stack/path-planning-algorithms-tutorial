RRT：从随机样本长出一棵探索树

把连续空间的不可枚举问题变成一次次局部合法连接。看懂采样、最近邻、步长、碰撞与探索偏置的数学条件，才能判断 RRT 何时有用。

如果机器人能在连续空间里朝任意方向走，怎么列出所有邻居？

在细栅格上做 A*，可以离散出每个节点的四个或八个邻居；但一个机械臂具有多个关节，一个移动机器人还可能有朝向、速度和转弯约束。状态空间维度升高后，均匀列举所有状态往往迅速不可行。RRT（Rapidly-exploring Random Tree）的思路不是预先构造全部网格，而是从起点生长一棵稀疏的树，并反复向随机选中的状态尝试延伸。

最基础的几何 RRT 在某些正则性假设下有概率完备性：若存在具有足够裕量的可行路径，采样数趋于无穷时发现路径的概率趋于 1。它没有在有限迭代内必定成功的承诺，也不保证找到的第一条路线最短。原始思路由 LaValle 1998 技术报告提出。

采样的是构型状态，不一定是地图坐标

用 X_free 表示满足碰撞、关节范围与其它几何约束的自由构型空间。二维点机器人可以使用 (x,y)；有朝向的车可能需要 (x,y,θ)，机械臂状态通常是多个关节角。这些变量的距离度量、周期性（θ 与 θ+2π）和约束都应纳入最近邻与扩展器。

二维教学模型取工作区 [0,10]²，矩形墙 [4,6]×[2,8]，起点 (1,5)、目标 (9,5)，机器人被近似为一个无尺寸点。在这个模型里欧氏距离和直线 steer 是有意义的；对于非完整运动学的汽车，直接连线则未必可执行。

边界先于算法：先定义 StateValid(q) 和 MotionValid(a,b)，再讨论如何采样。即使所有采样端点合法，穿过墙的线段也必须拒绝。

最短的 RRT 循环只有四个动词

  1. Sample：从构型空间抽取 q_rand，通常需要有非零概率覆盖所有值得探索的自由区域。
  2. Nearest：在已接纳树顶点中选距离采样点最近的 q_near。
  3. Steer：朝采样方向尝试移动至多步长 η，产生 q_new；它可能到不了采样点。
  4. Collision：若整段 q_near→q_new 合法，则增加顶点与父边；否则丢弃本次尝试。
qnew=qnear+min⁡(1,η‖qrand−qnear‖)(qrand−qnear)(1) 欧氏点机器人、最大扩展长度 η 的线性 Steer

这里的 η 具有与坐标相同的长度单位。过大容易尝试穿墙、拒绝率增加；过小会生成更多中间节点，也可能提高最近邻查询成本。goal bias 指在一定概率下把目标直接用作本次采样点，但目标也必须满足状态合法性，且连接目标的整条边必须检查。

Voronoi 偏置：为什么稀疏方向更容易得到新树枝

每个树顶点都有一个 Voronoi 区域：空间中离该点比离任何其它树顶点更近的那些采样位置。若在整个工作区均匀取样，Voronoi 区域越大的顶点，被选为“最近邻”的概率就越高。树的外围顶点通常拥有更大的区域，从而更容易被选择向未知方向生长，形成常说的探索偏置。

这里的“概率大”由几何区域体积决定，不等于对每个叶子显式赋不同概率，也不是算法直接优化最短路径。若采样分布不均匀、距离不是欧氏度量，或障碍导致有大片不可达区域，这种直觉还要结合真实采样与扩展算子理解。

检验一个点，和检验一段运动，不是一回事

在墙的一侧采到合法 q_near，在另一侧得到合法 q_new，端点都不在障碍里，直线仍有可能穿墙。需要检查整条局部运动，通常把机器人足迹障碍膨胀为构型空间禁区，或调用连续几何碰撞检测器。教学代码采用间隔不大于 0.05 的离散点检查，这只能在本例中起到近似作用；没有清晰的几何保守界时，离散检测不能证明连续运动完全不碰撞。

对移动障碍还要携带时间或速度；对汽车不能用欧氏线段取代可行转弯。反过来，即使局部段完全无碰撞，也不自动保证动力学、加速度或控制器跟踪约束。

固定随机种子的可运行二维 RRT

下面是完整的本示例二维点机器人 RRT：固定随机种子、最大 3000 次试探、15% 目标偏置、最大步长 0.48，终点只能经由合法短边接入。Python 3.10+ 标准库即可执行。所有实验数字只描述这张人工构造的矩形地图，绝非算法速度/成功率基准。

from math import dist
from random import Random

def rrt(seed=17, max_trials=3000):
    rng = Random(seed)  # 固定种子用于复现，不保证任意地图都能成功
    start, goal = (1.0, 5.0), (9.0, 5.0)
    wall = (4.0, 2.0, 6.0, 8.0)
    step = 0.48

    def free(q):
        x, y = q
        return (0 <= x <= 10 and 0 <= y <= 10
                and not (wall[0] <= x <= wall[2]
                         and wall[1] <= y <= wall[3]))

    def edge_free(a, b):
        # 最多相隔 0.05 的离散验证；生产代码请用连续/保守碰撞检查
        n = max(1, int(dist(a, b) / 0.05) + 1)
        for i in range(n + 1):
            t = i / n
            q = (a[0] + (b[0]-a[0])*t, a[1] + (b[1]-a[1])*t)
            if not free(q):
                return False
        return True

    def steer(a, b):
        d = dist(a, b)
        if d < 1e-12:
            return a
        k = min(1.0, step/d)
        return (a[0] + k*(b[0]-a[0]), a[1] + k*(b[1]-a[1]))

    vertices, parents = [start], [-1]
    for _ in range(max_trials):
        target = (goal if rng.random() < 0.15
                  else (10*rng.random(), 10*rng.random()))
        k = min(range(len(vertices)),
                key=lambda j: dist(vertices[j], target))
        new = steer(vertices[k], target)
        if dist(new, vertices[k]) < 1e-9:
            continue
        if not edge_free(vertices[k], new):
            continue
        vertices.append(new)
        parents.append(k)
        if dist(new, goal) <= step and edge_free(new, goal):
            vertices.append(goal)
            parents.append(len(vertices)-2)
            break
    else:
        return None, vertices  # 预算内未发现路径 ≠ 不可达证明

    route, idx = [], len(vertices)-1
    while idx >= 0:
        route.append(vertices[idx])
        idx = parents[idx]
    return route[::-1], vertices

route, tree = rrt()
assert route is not None and route[0] == (1.0, 5.0)
assert route[-1] == (9.0, 5.0)
assert len(tree) > len(route) >= 3
assert rrt(seed=17)[0] == route
print("seed=17: path found, all points within workspace;",
      "tree nodes:", len(tree))

断言验证非空路径、端点、树拓扑的基本长度关系，以及相同随机种子获得相同路线。若耗尽预算，返回 None 代表“这次没有发现”，而不是数学上“无路可走”。

三种常混淆的性质：概率完备、最优、可执行

问题基础几何 RRT为什么仍要小心
有路一定能找到？在正则性/鲁棒可行等条件下，随采样增长概率趋近 1窄通道与有限预算可能长时间失败
找到的是最短路？不保证渐进最优贪婪树结构不会主动重新优化父边
机器人能实际执行？只在所选状态与局部扩展模型下合法点机器人直线模型省略了动力学和真实足迹
运行速度一定更快？无普适速度保证最近邻查询、碰撞检测与空间维度很关键

若希望越采越接近最优成本，必须改变树的连接策略：RRT* 的选择父节点与重连正是针对这个问题，而不仅是“多采一些点”。
